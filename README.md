# D&D 面板 · 托管自动更新

固定加载器只需安装一次。它从本仓库的 `channel/stable.json` 获取已发布版本，下载并校验运行包后加载面板。页面显示的是实际启动的版本与代码指纹。

## 第一次安装

1. 下载仓库根目录的 [`loader.json`](https://raw.githubusercontent.com/didhogg/dnd-panel-updates/main/loader.json)。
2. 在原角色的酒馆助手脚本库导入它，明确启用“D&D面板_在线自动更新加载器”。酒馆助手4.11.3会把导入文件作为新的关闭条目，不会按导出ID覆盖旧脚本。
3. 点面板页头版本号，检查并停用其他D&D副本。若显示的仍是旧面板，也可在助手脚本库直接停用旧D&D脚本，只保留加载器。
4. 等生成结束、人物草稿保存后，完整重新载入酒馆一次，清除旧版本遗留的匿名监听器。无需删除角色卡、聊天或玩家存档。

以后不用重复导入完整包。加载器在启动、回到窗口及前台约每分钟检查；相同版本不重复下载。网络、缓存、后台节流和未保存草稿可能延迟切换，状态会如实显示。当前行动/结果未处理、模态框或人物草稿未保存时等待；完成后自动继续。运行包仍在原酒馆助手脚本iframe中执行。

## 显示与恢复

- 页头显示实际运行版本；点版本号可立即检查更新或检查副本。
- “已核对托管版本”表示本次检查成功；“待更新”表示新包已下载，等待当前操作完成。
- 检查、校验或启动失败会显示错误；旧版不会被改名冒充最新版。
- 有合法离线缓存时，首次离线启动可继续使用它，明确标为离线版本；启动新包失败时尝试恢复已验证的上一版。
- 本加载器不读取或上传角色、聊天、物品或凭证。网络请求只获取公开程序文件，使用 `credentials: omit`。
- SHA-256检查文件一致性，不是作者签名。本仓库是已配置的可信代码来源。

## 发布下一版

在维护源码的项目中提升精确版本及递增序号，先完成该版检查并生成完整脚本JSON。然后在此更新仓库的干净克隆中执行：

```sh
python3 scripts/pack-hosted.py --artifact /path/to/new-script.json --out . --write
git add channel releases loader.json src scripts README.md NOTICES.md
git commit -m "Publish the verified panel release"
git push origin main
```

运行包路径含版本和内容指纹；不要改写旧运行包。构建器拒绝相同序号对应另一份代码或降级。`channel/stable.json`与新运行包在同一次提交中推送；玩家的加载器随后读取并更新。只有加载器协议发生变化才需要重新导入加载器。普通界面、逻辑及数据库更新均通过运行包发布。

压缩包使用浏览器内置gzip解压，当前客户端需要 `crypto.subtle`、`DecompressionStream`、模块脚本及允许访问GitHub原始文件的网络。能力或网络不满足时会明确报错，保留可用旧版或离线缓存，不从其他网站偷偷下载代码。

本仓库只放公开程序和发布元信息，不放角色卡、聊天、玩家数据或密钥。面板沿用既有全局变量存储，加载器缓存独立保存程序包。

原脚本及第三方规则、中文资料、库分别遵循其原授权；本项目并未将它们重新授权为MIT。请保留 [`NOTICES.md`](./NOTICES.md) 与运行包中的原始许可说明。本工具非Wizards of the Coast官方产品。

自动测试、公开文件传输检查、浏览器加载和真实酒馆导入分别验收。仓库已发布不等于任意客户端已安装或已通过全部规则/交互检查。
